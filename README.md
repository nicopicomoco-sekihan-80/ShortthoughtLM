思考圧縮・自己改善AI
Architecture Design Document v0.1
1. 目的

本プロジェクトは、人間の「反省 → 意識的な思考 → 練習 → 習慣化 → 無意識化」という学習過程を模倣し、LLMの推論過程を段階的に圧縮するシステムを構築する。

目的は、回答精度を可能な限り維持しながら、推論に必要なトークン数・計算量を削減すること。

モデル自身の構造を自律的に改造することは目的としない。

2. 基本コンセプト

通常のLLM：

問題
 ↓
長いCoT
 ↓
回答


本システム：

問題
 ↓
長いCoT
 ↓
重要な思考を抽出
 ↓
短い思考単位
 ↓
学習
 ↓
短い思考で回答


さらに子モデルが失敗した場合、

子の失敗
 ↓
親モデルが分析
 ↓
失敗原因を特定
 ↓
新しい思考単位を生成
 ↓
子に意識的に使用させる
 ↓
LoRA学習
 ↓
思考単位の内部化


というループを形成する。

3. 設計思想
3.1 親モデル

親モデルは「教師」として扱う。

要件：

子より高い推論能力

比較的高い正答率

詳細な推論を生成できる

大量生成可能な程度には軽量

初期モデル：

Qwen3-1.7B

将来的に3B、7B等へ変更可能とする。

3.2 子モデル

子モデルは、親モデルの長い推論をそのまま再現することを目的としない。

目的：

必要な思考だけを使用する

推論トークン数を削減する

親と同等以上の正答率を目指す

初期段階では親と同じベースモデルを使用し、LoRAによって子モデルを構築する。

Base Model
    │
    ├── Parent
    │
    └── Child + LoRA

5. コンポーネント
5.1 Parent

役割：

問題を解く

詳細な推論を生成する

子の失敗を分析する

失敗原因を特定する

新しい思考単位を提案する

出力例：

問題:
5 + 3 × 2

推論:
掛け算は足し算より先に処理する。
3 × 2 = 6。
5 + 6 = 11。

回答:
11

5.2 Thought Extractor

親の長いCoTから、問題解決に必要な情報を抽出する。

入力：

掛け算は足し算より先に処理する。
3 × 2 = 6。
5 + 6 = 11。


出力：

×先


または、

×先 → 6 → 11


抽出結果は「思考単位（Thought Unit）」として保存する。

5.3 Child

圧縮された思考単位を利用して問題を解く。

例：

入力:
5 + 3 × 2

思考:
×先

回答:
11


学習が進むと、

入力:
5 + 3 × 2

回答:
11


となることを目標とする。

これは「思考の削除」ではなく、思考の内部化・自動化と解釈する。

5.4 Evaluator

子の回答を評価する。

最低限、

correct / incorrect


を判定する。

将来的には、

正答率

推論トークン数

推論時間

思考単位使用率

失敗パターン

過学習

などを記録する。

5.5 Failure Analyzer

子が間違えた場合のみ起動する。

入力：

問題
子の思考
子の回答
正解
親の推論


親モデルが分析し、

失敗原因：
演算子の優先順位を考慮していない

必要な思考：
掛け算を先に処理する

思考単位：
×先


を生成する。

重要：

失敗分析は子自身ではなく親が行う。

5.6 LoRA Trainer

Failure AnalyzerおよびThought Extractorから生成されたデータを使用して子モデルを更新する。

基本形式：

Input:
5 + 3 × 2

Thought Unit:
×先

Answer:
11


複数データを一定量蓄積してからLoRA学習を行う。

逐次1件ずつLoRA更新するのではなく、バッファリングしてまとめて学習する。

7. 思考単位

思考単位は、人間の「考え方の癖・習慣」に相当する。

例：

×先
括弧先
単位確認
符号確認
境界確認
条件確認
逆算
場合分け


思考単位は必ずしも自然言語である必要はない。

初期実装では短い自然言語トークンを使用する。

将来的には専用トークンの導入を検討する。

8. 思考圧縮

圧縮率を重要な評価指標とする。

例：

Original CoT:
50 tokens

Compressed Thought:
3 tokens

Compression Ratio:
94%


ただし、圧縮率だけを最大化しない。

最優先：

正答率


次点：

推論コスト


したがって目標は、

Accuracy ≈ Parent
Reasoning Tokens ↓


とする。

9. 人間の学習との対応
人間	本システム
失敗	Childの誤答
反省	Parent Analysis
「次からこうする」	Thought Unit
意識して実践	Thought Unitを明示的に使用
繰り返し練習	LoRA学習
習慣化	モデル内部への定着
無意識化	Thought Unitなしで成功
熟練	短い推論で高精度
10. 世代構造

初期版では世代を作らず、

Parent
   ↓
Child


のみとする。

将来的には、

Parent 0
   ↓
Child 1
   ↓
Child 2
   ↓
Child 3


という世代型学習を可能にする。

ただし、各世代で正答率が低下しないことを検証する。

11. 最初の実験

最初から汎用AIを目指さない。

Phase 0

算数のみ。

例：

5 + 3 × 2
12 ÷ 3 + 7
8 + 4 × 5
(5 + 3) × 2


10〜50問程度から開始。

Phase 1

親によるCoT生成。

問題
→ Parent
→ Long CoT
→ Answer

Phase 2

思考圧縮。

Long CoT
→ Thought Extractor
→ Thought Unit

Phase 3

Childに圧縮思考を与えて評価。

Phase 4

ChildをLoRA学習。

Phase 5

意図的にChildが失敗する問題を作り、

Child Failure
→ Parent Analysis
→ New Thought Unit
→ LoRA
→ 再評価


を検証する。

12. 成功条件

第一実験の成功条件：

1. Parentが正しく解ける
2. Childが圧縮思考で正しく解ける
3. LoRA後も正答率が維持される
4. 推論トークン数が減少する
5. 未学習問題でも効果が確認できる


特に重要なのは 5。

学習データを丸暗記しただけでは、本研究の目的を達成していない。

14. 初期実装でやらないこと

以下は初期バージョンでは実装しない。

モデル自体の構造変更

自律的なコード書き換え

自律的なモデル選択

複雑な強化学習

巨大モデル

完全自動のデータ生成システム

複雑な長期記憶

人間の脳全体の模倣

まず、

「失敗 → 親による分析 → 思考単位 → LoRA → 改善」

が成立するかだけを検証する。

15. 最終的な仮説

本プロジェクトが検証する中心仮説：

LLMの長いCoTから問題解決に重要な思考単位を抽出し、失敗時に教師モデルから新しい思考単位を獲得してLoRAで学習することで、推論能力を維持しながら推論過程を段階的に圧縮できる。

さらに、

明示的な思考単位を繰り返し使用・学習することで、最終的にはその思考単位を明示せずに同じ処理を実行できるようになる。

これを本プロジェクトの主要仮説とする。
